# Практическая работа 3 Разработка внутренней логики программы

Дисциплина: «Проектирование аналитических систем». Автор: Ахтямов Т. Р., группа ИМБО-10-23.

## Цель работы

Реализовать внутреннюю логику аналитической системы прогнозирования месячной инфляции Российской Федерации. Программа организована как независимые модули обработки, анализа и визуализации, вызываемые из основного файла. Горизонт равен одному месяцу; модели — обычная линейная регрессия и Ridge. GUI относится к следующей практической работе и будет использовать эти же функции.

## Модуль обработки данных

`download(url, path, log_path)` загружает ответ с таймаутом и тремя попытками. Исходные HTML/XML сохраняются без преобразования. В журнал JSONL записываются URL, время загрузки, размер ответа, статус и ошибка. Одинаковые месяцы после повторной загрузки не дублируются; успешный ответ заменяет локальную копию. Это полная повторная загрузка, а не инкрементальное хранилище исторических версий.

`parse_cpi_html(text)` преобразует таблицу «месяц × год» во временной ряд. Выбираются только двенадцать названий месяцев; строки итогов за год не используются. Из индекса к предыдущему месяцу вычитается 100. Например, 100,40 становится 0,40% м/м. Десятичная запятая обрабатывается явно.

`collect(start_year, end_year, raw_dir)` собирает таблицы ИПЦ и дневной официальный курс USD/RUB. Значение XML делится на номинал валюты. Курс агрегируется средним по опубликованным дням месяца, затем вычисляется процентное изменение относительно прошлого месяца. Дневной курс на выходных искусственно не создаётся. ИПЦ и изменение курса объединяются по месяцу.

`validate(frame)` требует непрерывного месячного ряда, уникальных дат, первых чисел месяцев, числовых конечных значений и разумных границ месячной инфляции. Пропуски не интерполируются: программа сообщает об ошибке, чтобы не создавать признаки из будущих значений. Минимальная длина исходного ряда — 72 месяца; дополнительно проверяется достаточная длина обучающего окна.

`load_csv(path)` принимает CSV в UTF-8 с разделителем-запятой, столбцами `date,cpi_mom` и необязательным `usd_rub_mom`. Дата имеет вид `2024-01-01`. Обе числовые колонки содержат процентные изменения, а не уровни. Дополнительные столбцы не включаются автоматически в признаки.

`make_features(frame)` формирует отдельную строку для каждого прогнозируемого месяца и следующего месяца после последнего факта. Для целевого месяца m используются:

- ИПЦ за m−1, m−2, m−3 и m−12;
- средние месячные приросты ИПЦ за 3 и 12 завершённых месяцев;
- изменения USD/RUB за m−1, m−2 и m−3, если курс присутствует;
- синус и косинус номера прогнозируемого месяца.

Сначала применяется сдвиг, затем скользящее среднее. Первые 12 месяцев исключаются только из обучающих строк, но остаются в исходной истории. Последняя строка признаков относится к будущему месяцу, поэтому у неё отсутствует целевое значение.

## Модуль анализа данных

### Регрессионные модели

Обычная линейная регрессия минимизирует сумму квадратов ошибок. Ridge добавляет штраф alpha × сумму квадратов коэффициентов. Все признаки стандартизуются внутри `Pipeline`; средние и стандартные отклонения вычисляются только на обучающей части каждого разбиения.

`fit_model(x, y, name)` обучает модель. Для Ridge перебираются alpha = 0.1, 1, 10, 100, 1000; критерием служит MAE на трёх последовательных временных разбиениях `TimeSeriesSplit`. Для линейной регрессии та же процедура оценивает качество без подбираемых гиперпараметров. ARIMA, SARIMA и бустинг не применяются.

### Временное бэктестирование

`evaluate(x, y, cpi, test_months)` последовательно прогнозирует последние 36 месяцев. На каждой итерации доступны только предыдущие строки; обучающее окно расширяется. Параметр Ridge заново подбирается исключительно внутри текущего обучающего окна. Таким образом, тестовый месяц не участвует ни в стандартизации, ни в подборе alpha.

Сезонный наивный прогноз равен месячному приросту ИПЦ за тот же календарный месяц предыдущего года. Он нужен как контрольный ориентир, а не как дополнительная основная модель. Прогнозы всех трёх вариантов сохраняются; программа не выбирает победителя по внешней тестовой выборке.

### Метрики

- MAE — средняя абсолютная ошибка в процентных пунктах.
- RMSE — корень средней квадратичной ошибки в процентных пунктах.
- MASE — абсолютная ошибка, делённая на среднюю абсолютную сезонную разность ряда в обучающей истории; затем результат усредняется по проверочным месяцам.

Знаменатель MASE вычисляется отдельно для каждого начала прогноза, без проверочных значений. Если сезонные разности нулевые, MASE не определён и записывается как пропуск. MASE ниже 1 означает ошибку меньше средней сезонной разности обучающей истории; это не то же самое, что гарантированная победа над сезонной моделью на тестовом периоде. Сравнение на тесте выполняется непосредственно по MAE и RMSE моделей.

MAPE исключён, поскольку месячная инфляция бывает близкой к нулю и отрицательной.

### Прогнозные интервалы

`interval(errors, prediction, coverage)` использует эмпирические квантили прошлых ошибок «факт минус прогноз» и возвращает 80% и 95% интервалы. Для визуальной и смысловой согласованности диапазон расширяется до включения точечного прогноза, если все ошибки одного знака. Минимальное число ошибок — 12.

В бэктесте ошибка текущего месяца добавляется только после построения интервала. Первые 12 прогнозов интервалов не имеют. Фактическое покрытие считается только на оставшихся прогнозах; отдельно сохраняется число таких наблюдений. Для следующего месяца используются все ошибки завершённого бэктеста. Интервалы приближённые: структурные сдвиги и малый объём калибровки не позволяют гарантировать номинальное покрытие.

`forecast(x, y, future_x, predictions)` переобучает обе модели на доступной истории, сохраняет следующий месячный прогноз, выбранный alpha, внутреннюю MAE и интервалы. Коэффициенты относятся к стандартизованным признакам и показывают условную связь; причинное влияние ставки, курса или иных факторов по ним не устанавливается.

## Модуль визуализации

`save_figures(...)` принимает готовые результаты и создаёт три автономных HTML-файла с Plotly:

1. Историческая инфляция, бэктест всех моделей и два прогноза на следующий месяц с 95% интервалами.
2. Сравнение MAE и RMSE.
3. Коэффициенты стандартизованных признаков.

Графики сохраняются вместе с JavaScript и открываются без подключения к интернету. В `index.html` представлены ссылки на графики и выгрузки. Данные также доступны в CSV и JSON, что позволит подключить Streamlit в ПР4 без переноса вычислений в интерфейс.

## Основной файл и запуск

Рекомендуется Python 3.11 или новее. Из корня репозитория:

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# Linux / macOS
# source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py --input data/reference/monthly.csv
```

Для новой сетевой загрузки:

```bash
python main.py --download --start-year 2010 --end-year 2026
```

Собственный набор:

```bash
python main.py --input path/to/monthly.csv --test-months 36 --output reports/generated/my_run
```

Минимальный формат CSV:

```csv
date,cpi_mom,usd_rub_mom
2010-01-01,1.6,0.5
2010-02-01,0.9,-1.2
```

Этот фрагмент показывает только формат; для обучения нужны не менее 72 непрерывных месяцев.

Выполнение проверок:

```bash
# Windows PowerShell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -v
# Linux / macOS
# PYTHONPATH=src python -m unittest discover -s tests -v
```

## Ограничения реализации

Момент прогноза — после публикации ИПЦ за последний завершённый месяц t, целевой месяц — t+1. Поэтому на фактическую дату запуска целевой календарный месяц уже может идти. Лаги исключают использование наблюдений за целевой месяц, но исторические даты публикаций и версии пересмотра ИПЦ не восстановлены. Полученный бэктест является ретроспективным на актуальной версии данных, а не строгим real-time бэктестом.

ИПЦ загружается из вторичной публикации Audit-it, поскольку прямой доступ к Росстату при реализации возвращал HTTP 503. Это обозначено в метаданных; вторичный источник не выдаётся за прямой API Росстата. Из внешних факторов в ПР3 реализован только USD/RUB. М2, ИЦП, безработица, Brent и ключевая ставка пока не подключены: для них нужны отдельные проверки дат публикации и трансформаций.

Сырая загрузка сохраняется локально и журналируется, но полное версионирование наблюдений и инкрементальная загрузка остаются дальнейшим развитием. GUI, автоматический ежемесячный запуск, сценарный анализ и оценка отклонения годовой инфляции от цели 4% не входят в реализованную ПР3.
